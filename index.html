AI-Assisted Engineering

  • Agent-driven development with a verification loop: a substantial share of my work is produced with an AI coding agent and none of it is trusted on sight — changes are exercised in a real headless browser over the Chrome DevTools Protocol, measured before and after, and reverted byte for byte when the measurement contradicts the claim
  • Harness before feature: every new construct ships with a validator, so a malformed input is named on the command line instead of rendering as silent emptiness — the role an eval suite plays in an LLM product
  • Sandboxed execution of untrusted code: reader-submitted code runs in an isolated frame and is graded by behavioural assertions rather than text comparison, because a real problem has several correct answers
  • Scoring instead of pass/fail: an exercise can report that the code works and could have been written better, which is usually the truthful answer
