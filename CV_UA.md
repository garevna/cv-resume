#### 7. Модульна фронтенд-платформа (у активній розробці)
Платформа онлайн-бронювання міжнародних автобусних перевезень спроєктована як перевикористовуване ядро, що обслуговує кількох незалежних перевізників за white-label-моделлю. 

Увесь процес бронювання реалізовано всередині цього ядра як Vue-плагін.

Спроба розв'язати проблему, що виникла природно: кілька сайтів із однаковою бізнес-логікою й дедалі більшим дублюванням коду. Спільне винесено у версійовані пакети:

**Архітектура**:

* **Монорепозиторій** на pnpm workspaces, розділений за відповідальністю:

| Пакет |	Відповідальність |
|-|-|
| @company/app-types | типи, енуми, спільні утиліти |
| @company/app-services |	робота з API |
| @company/event-manager |	подієва шина застосунку |
| @company/shared-ui	| бібліотека UI-компонентів |
| @company/wizard-core |	візард бронювання як окремий продукт |

Додатки для різних клієнтів складаються з цих пакетів.

* **Інверсія залежностей**: ядро не імпортує сторі застосунку — натомість хост реєструє їх через registerStoresFor*(), що й забезпечує можливість багаторазового використання.

* **Конфігурований флоу**: WizardStep з предикатами isEnabled / canEnter / canLeave та WizardFlowConfig дають змогу описувати порядок кроків декларативно.

**Функціональність**:

* Пошук поїздок туди-назад з побудовою маршруту через пересадки
* Інтерактивна схема салону з реальними планами розсадки, типами місць і автоматичним підбором місць для груп
* Синхронізація доступності місць у реальному часі через WebSocket з автоперепідключенням і ping-моніторингом
* Пасажири з типами місць і знижками, покроковий перерахунок вартості в кількох валютах
* Повний життєвий цикл: бронювання → оплата → PDF-квитки → email → скасування / повернення
* Особистий кабінет з історією, програмою лояльності та акціями
* Трансфери «від дверей до дверей»: геолокація, зони на MapLibre, розрахунок вартості
* Три мови (uk/en/de) з локалізованими форматами

Найсильніше рішення — wizard-core. Візард бронювання — найскладніша й найцінніша частина всієї системи. Винести саме його в окремий пакет означає, що будь-який новий сайт замовника отримує готову працюючу воронку продажів, а не її копію, яку доведеться підтримувати окремо. Це рішення продуктове, не лише технічне.

Патерн реєстрації (registerAppServicesConfig, registerStoresForEventManager) розв'язує справжню проблему: спільні пакети не можуть імпортувати сторі застосунку, бо тоді залежність стає циклічною й пакет перестає бути спільним. Інверсія залежності через реєстрацію на старті — коректний спосіб це обійти.

**Стек**: Vue 3 (Composition API), TypeScript, Vite, Vuetify 3, Pinia + persisted state, Vue Router, vue-i18n, MapLibre GL, Firebase Auth, WebSocket, Axios, libphonenumber-js, pnpm workspaces

**Статус**: доменне ядро, шар API, UI-бібліотека та основний процес бронювання реалізовані повністю. 

*Наступний етап* — декларативна конфігурація флоу та підключення клієнта другого перевізника.

#### 8. Візуальний редактор контенту
Березень 2026 — донині · версія 10.0.0 · Vue 3, TypeScript, Vuetify 3, IndexedDB, CodeMirror

Інструмент, що передає керування сайтом самому замовнику: блоковий конструктор сторінок із редагуванням на місці, UI Kit для керування дизайн-системою (палітра, типографіка, кнопки, вкладки, відступи), конструктор футера, мультимовність, чернетки в IndexedDB з явною публікацією, ізольоване вікно попереднього перегляду, SEO-інструменти.

Завершує логіку всієї послідовності: від сайту, зробленого руками, до сайту, яким замовник керує без розробника.

**Архітектура та дизайн:**

- Розроблена система рантайм-завантажуваної теми та контенту: на старті додаток завантажує палітру, шрифти, CSS та контент сторінок з сервера, що дозволяє розгортати продукт для нових брендів/клієнтів **без пересборки фронтенда**
- Офлайн-фолбек на вбудовані дані при недоступності бекенду
- Централізований state-менеджмент (Pinia) з гарантованою синхронізацією три-апів: редактор → превью → production

*Ключові функції:*
- **Багатокроковий флоу бронювання:** пошук рейсів → вибір маршруту (з пересадками) → вибір місць на схемі автобуса → трансферти (pickup/dropoff) → дані пасажирів → оплата → підтвердження
- **Персональні трансферти:** інтерактивний вибір точок посадки/висадки на карті, розрахунок вартості
- **Real-time синхронізація:** WebSocket з автоматичним переподключенням (експоненціальний backoff) для оновлення доступності місць та статусів
- **Мультиязичність:** uk/en/de через vue-i18n з локалізацією дат, валют, телефонних номерів
- **Аутентифікація:** Firebase Auth (email/пароль, SMS+reCAPTCHA, Google)
- **SEO для краулерів:** динамічні meta-теги, настройка індексації для AI-ботів (GPTBot, ClaudeBot)

**Візуальний редактор у зв'язці з клієнтським сайтом**

Це найзріліше архітектурне рішення з усіх перелічених, тому що воно змінює бізнес-модель, а не лише код: сайт перестає потребувати розробника для щоденних змін.

Ключова ідея — редактор і сайт читають один і той самий JSON. Редактор не генерує код і не тримає власного формату: він редагує ті самі дані, які прод рендерить у продакшені. Це усуває цілий клас неузгодженостей, які виникають у генераторах сайтів.

Головний виклик, закладений у цю конструкцію, — три рендерери. Редактор, вікно попереднього перегляду й клієнтський сайт малюють одні й ті самі дані трьома різними кодовими базами. Вимога «редактор показує рівно те, що побачить відвідувач» означає, що будь-яка зміна має бути внесена тричі, а розходження проявляється не помилкою, а тихо зниклим блоком.

Це не хиба задуму — це його ціна, і вона усвідомлена: кожен новий тип блоку доводиться навчати всі три сторони. Логічний наступний крок — саме той, який уже почато в монорепозиторії: винести рендерер блоків у спільний пакет, щоб редактор і сайт використовували один і той самий код відображення, а не три його копії.

Зв'язка редактора з монорепозиторієм — природне завершення обох ідей. Монорепозиторій знімає дублювання логіки між сайтами, редактор знімає залежність контенту від розробника. Разом вони дають те, до чого вела вся послідовність із восьми проєктів: тиражований продукт, який замовник отримує готовим і веде самостійно.

**Стек**: Vue 3 (Composition API), TypeScript, Vuetify 3, Pinia, Vite, vue-i18n, Firebase Auth.

## Компетенції

### Performance & Optimization
- **Web Workers + IndexedDB:** розподіл обчислювальної роботи між потоками браузера, обробка великих обсягів даних без постійних запитів до сервера, розвинена система індексів
- **Bundle optimization:** code splitting, dynamic imports, lazy loading
- **Frontend performance:** оптимізація LCP, FID, CLS; профілювання та діагностика

### Architecture & Design Patterns
- Розробка масштабованих архітектур складних додатків
- State management (Pinia, Vuex) з гарантованою консистентністю даних
- Component-driven development з переиспользуваними UI-паттернами
- API integration та обробка помилок

### Real-time & Data Sync
- WebSocket-обробка з автоматичним переподключенням
- Синхронізація кількох додатків (редактор + превью + production)
- Offline-first strategies з фолбеком

### Accessibility & SEO
- Семантична розмітка, ARIA-атрибути
- Dynamic meta-tags для SEO та AI-краулерів
- Тестування зі скринридерами

### Mentoring & Communication
- 3+ років менторства junior-розробників у IT-школах
- Залучення студентів до комерційних проектів для отримання реального досвіду
- Прямий контакт з C-level для обговорення архітектурних рішень
- Вивід проектів та переговори з клієнтами
